# Flujo de trabajo con Git y GitHub

1. Actualizar la rama principal antes de empezar.
2. Trabajar en una rama específica por módulo o tarea.
3. Hacer commits pequeños y descriptivos.
4. Subir la rama al repositorio.
5. Abrir un pull request hacia `main`.
6. Revisar los cambios y comprobar la compilación del firmware antes de fusionar.
7. Guardar capturas de pantalla como evidencia de los pasos realizados.

## Nombres de ramas
- `feature/sensores`
- `feature/alerta-buzzer`
- `feature/comunicacion-gps-gsm`
- `docs/guia-proyecto`

## Reglas del equipo
- No subir contraseñas, tokens ni archivos de secretos.
- No marcar un módulo como terminado hasta probarlo en el hardware real.
- Explicar en el pull request qué cambió y cómo se probó.
